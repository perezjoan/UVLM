UVLM — Version History
======================

v3.2.0 (August 2026) — InternVL3.5 backend, per-model output filenames
--------------------------------------
  - Added: InternVL3.5 backend ("internvl") supporting 6 new checkpoints:
    InternVL3.5 1B / 2B / 4B / 8B / 14B / 38B, using the Transformers-native
    "-HF" variants from OpenGVLab. Registry now totals 21 checkpoints across
    4 families. The family appears automatically in the notebook selector via
    FAMILY_GROUPS (no notebook changes required for the new family).
  - Added: InternVL inference path in inference.py. Unlike the Qwen pipeline,
    InternVL3.5-HF uses the standard Transformers pattern: the chat template
    tokenizes directly (apply_chat_template with tokenize=True,
    return_dict=True), generated tokens are sliced off after the prompt, and
    only the generated portion is decoded. Float inputs (pixel_values) are
    cast to the model's compute dtype so BF16, FP16, and 4-bit loads all work.
  - Changed: loader.py — the AutoModelForImageTextToText branch now serves
    both qwen3 and internvl backends, with the min/max pixel budget applied
    only to Qwen3-VL. BF16-aware dtype selection applies to both families.
  - Fixed: batch output filenames are now derived from the loaded checkpoint
    (e.g. Score_Analysis_InternVL3_5-8B-HF.csv). Previously the notebooks
    used a two-backend-era rule that sent every non-Qwen2.5 backend to
    Score_Analysis_LLaVA.csv, which allowed different models to append into
    the same CSV and contaminate resume mode. Resume and schema upgrades are
    now per-model as a side effect. Applies to both notebooks.
  - Notes: InternVL3.5-HF checkpoints are not gated (no Hugging Face token
    required). No dependency changes — transformers >= 4.52.1 is required by
    the family and already covered by the existing >= 4.57.0 floor.

v3.1.0 (August 2026) — Qwen3-VL backend, family-based model selection
--------------------------------------
  - Added: Qwen3-VL backend ("qwen3") supporting 4 new checkpoints:
    Qwen3-VL 2B / 4B / 8B / 32B Instruct. The family shares the Qwen
    inference pipeline (chat template -> process_vision_info -> generate ->
    token trimming) and is loaded via the generic AutoModelForImageTextToText
    class. Registry now totals 15 checkpoints across 3 families.
  - Added: BF16-aware dtype selection for the qwen3 backend — BF16 is used
    automatically on GPUs with native support (RTX 30xx+, L4, A100), with
    FP16 fallback on older GPUs and FP32 on CPU. Mitigates the FP16
    numerical-overflow crashes previously observed with BF16-trained
    checkpoints on T4-class hardware.
  - Added: FAMILY_GROUPS mapping in registry.py (family name -> model dict),
    exported at package level. Adding a future family to the notebooks now
    requires only a registry entry.
  - Changed: Both notebooks (Colab and local) now use a two-level model
    selector — choose the family first (LLaVA-NeXT / Qwen2.5-VL / Qwen3-VL),
    then the model. The model list refreshes automatically per family.
  - Added: Log output area in the local notebook (Block 1). Model download
    progress bars and loading messages emitted inside the widget callback
    are now displayed under the Load button (previously swallowed in local
    Jupyter; Colab was unaffected).
  - Changed: from_pretrained calls use the `dtype` keyword instead of the
    deprecated `torch_dtype` (silences deprecation warnings on
    transformers >= 4.56; identical behavior).
  - Changed: dependency floors raised — transformers >= 4.57.0 (required by
    Qwen3-VL) and qwen-vl-utils >= 0.0.14 (Qwen3-VL resizes images to
    multiples of 32 px instead of 28 px). Upper bound transformers < 5.0.0
    unchanged.
  - Fixed: __init__.py version string synchronized with pyproject.toml
    (previously reported 3.0.0 while the package metadata said 3.0.2).

v3.0.2 (June 2026) — Renamed to Unified, reproducible example, Zenodo archive
--------------------------------------
  - Renamed: U in UVLM changed from "Universal" to "Unified" to better
    reflect the tool's scope (unified interface across VLM families).
  - Added: Sample image (D09.jpg) for minimal reproducible example.
  - Added: Minimal reproducible example in README (5 lines of Python).
  - Added: Hardware requirement per model
  - Added: Zenodo DOI for permanent code archival.
  - Updated: README to reflect naming change and add example section.
  - bump version to 3.0.2

v3.0.1 (May 2026) —  fix: package discovery, transformers upper bound, device mismatch on generate
--------------------------------------
  - pyproject.toml: replace packages.find with explicit packages=["uvlm"] to
    fix pip install producing UNKNOWN-0.0.0 with no module files
  - pyproject.toml: tighten transformers to >=4.47.0,<5.0.0 — 5.x introduces
    breaking weight conversion that crashes Qwen2.5-VL on load
  - inference.py: fix _move_inputs_to_model_if_needed returning inputs on CPU
    when device_map="auto" (main_device=None); fall back to cuda:0 instead,
    fixing device mismatch crash on model.generate() with 4-bit quantization
  - bump version to 3.0.1

v3.0.0 (April 2026) — Package release
--------------------------------------
- Refactored: Monolithic Colab notebook into pip-installable Python package
  (uvlm/) with 8 modules: loader, inference, parsers, consensus, batch,
  prompts, registry, utils.
- Added: Local Jupyter notebook interface (notebooks/UVLM_local.ipynb) for
  running UVLM on local GPU hardware without Google Colab.
- Added: Google Colab notebook interface (notebooks/UVLM_colab.ipynb) that
  installs the uvlm package from GitHub automatically.
- Added: Programmatic API — load_model(), run_inference(), parse_response(),
  run_batch() can be called from any Python script without notebooks.
- Changed: All global state eliminated. Model, processor, and backend are
  passed as a model_ctx dict returned by load_model().
- Changed: run_inference() now returns (raw_response, token_count) tuple
  instead of storing token count in a global variable.
- Added: Environment detection (is_colab()) for automatic path and token
  handling across Colab and local deployments.
- Added: Unified HF token retrieval via get_hf_token() — tries explicit
  argument, Colab secrets, HF_TOKEN env var, and huggingface-cli cache.
- Added: pyproject.toml for pip installation from GitHub.
- Added: .gitignore for Python/Jupyter artifacts.
- Preserved: All inference, parsing, consensus, and batch logic unchanged
  from v2.2.2. No behavioral changes.

v2.2.2 (March 2026) — Initial public release
---------------------------------------------
- Added: Truncation detection for all task types using exact generated token
  count from model output.
  - New CSV column: {col}_truncated.
  - Console warning displayed when truncation is detected.
- Updated: Advanced reasoning mode automatically overrides token limit to
  ADVANCED_REASONING_MAX_TOKENS = 1024.
- Updated: Max tokens slider range extended to 1500 to allow user-defined
  reasoning budgets.
- Updated: Consensus validation runs extended to configurable range of 2–5.
- Fixed: Reasoning output column ({col}_reasoning) is no longer truncated.
- Fixed: UTF-8 encoding issues when writing CSV outputs.
- Added: Pre-configured benchmark notebooks with dynamic output filenames.

v2.2.1 (February 2026)
-----------------------
- Fixed: NA value handling in consensus validation. The compute_consensus()
  function now properly filters out NA values (failed parses) before majority
  voting, ensuring that parsing failures do not influence the final answer.
  Agreement ratio is still computed over all runs (including NA) to preserve
  the reliability metric.
- Added: is_na_value() helper recognizing "NA", "N/A", "NAN", "NONE", "NULL",
  empty strings, and None values.

v2.2 (January 2026)
--------------------
- Added: Advanced reasoning mode (chain-of-thought prompting).
  - Per-task checkbox to enable structured CoT prompting.
  - Auto-generated format instruction with "ANSWER: <value>" pattern.
  - Max token budget override: 1024 tokens (vs default 50).
  - Response parser scans last 5 lines for ANSWER: pattern.
  - Graceful fallback to standard parsing if format not followed.
  - Reasoning trace stored in {column}_reasoning CSV column.
- Added: Disabled advanced reasoning for "text" task type.

v2.1 (December 2025)
---------------------
- Added: Consensus validation feature.
  - Per-task toggle with configurable runs (2 or 3, default: 2).
  - Majority voting across all runs (equal peer voting).
  - Percentage-based numeric tolerance for grouping similar values.
  - Output columns: {col}_consensus, {col}_agreement, {col}_runs.
  - Consensus not available for "text" task type.

v2.0 (November 2025)
---------------------
- Added: Multi-task prompt builder with widget-based UI (up to 10 tasks).
- Added: Four task types: numeric, category, boolean, text.
- Added: Four-element prompt structure: role, task, theory, format.
- Added: Batch execution engine (Block 3) with image folder iteration.
- Added: Resume mode: skip already-processed images.
- Added: CSV schema upgrading: append new task columns to existing CSV.
- Added: Per-task error handling (errors logged as "NA").
- Added: Periodic checkpoint saves (every 5 images).

Note
----
Versions prior to **v2.2.2** were developed in a **private repository**.
The public GitHub release history therefore begins at **v2.2.2**.
